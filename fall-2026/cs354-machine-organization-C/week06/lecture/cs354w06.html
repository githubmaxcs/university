Allocator Opportunities (multiple free lists)

Segregated Free List

  • rather than searching one free list for allocation candidates, keep multiple lists
  • keep different lists for different sizes of block
  • when allocating, start by searching smallest block list that is big enough

Simple Segregated Free List

  • avoid splitting and coalescing blocks
  • manage multiple regions of blocks that are all the same size

benefits: drawbacks:

Segregated Fits

  • when blocks are split, the remaining fragments may end up in a different list
  • when a free list does not contain a block with the needed size, split from larger list
  • this best matches what the malloc() function we've been using does

sweeping: free up any unmarked (and therefore inaccessible) memory
